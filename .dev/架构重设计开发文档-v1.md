## 2. 新架构设计：前端 + 后端分离

### 2.1 分层原则

```
┌─────────────────────────────────────────────────────────────────┐
│  Frontend (UI Layer)                                            │
│  - Compose Screens / Dialogs / Sheets                           │
│  - ViewModel 状态持有（仅 UI 状态）                              │
│  - SAF 文件选择器、Toast、权限                                   │
│  - 不直接操作存档数据结构                                        │
├─────────────────────────────────────────────────────────────────┤
│  Presentation / State Management                                │
│  - GameViewModel：场景容器、命令分发、一次性事件                 │
│  - UiState：selectedUnitId, editMode, measureMode, replayState  │
├─────────────────────────────────────────────────────────────────┤
│  Backend (Domain + Data Layer)                                  │
│  - Engine：MovementEngine, TurnState, FogOfWar, ReplayEngine   │
│  - Domain Model：Unit hierarchy, Waypoint, Perception, Arc      │
│  - Codec：SpScnCodec, JsonUtil, MovementOrders                  │
│  - Repository：ScenarioRepository, SettingsRepository           │
│  - Services：SymbolGenerator, RangeGraphics, MapRenderer        │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 后端（Backend）：纯 Kotlin / JVM，可脱离 Android 测试

#### 2.2.1 领域模型重构：引入真正的类型体系

当前 `data.model.Unit` 是扁平 data class，靠字段推断类型。桌面版是显式继承树，Android 应建立对应 Kotlin 密封类/继承：

```kotlin
sealed class Unit(
    open val idNum: String,
    open val side: String,
    open val name: String,
    // ... common fields
)

sealed class MovableUnit : Unit(...) {
    abstract var speed: Int      // ×1000 knots
    abstract var course: Int     // ×1000 degrees
    abstract var range: Int
    abstract val futureWaypointArray: MutableList<Waypoint>
    abstract val pastWaypointArray: MutableList<Waypoint>
}

class AirUnit(...) : MovableUnit() {
    var altitude: Int? = null
    var assignedAltitude: Int? = null
    var climb: Int? = null
    var descend: Int? = null
}

class SurfaceUnit(...) : MovableUnit()
class SubsurfaceUnit(...) : MovableUnit() {
    var depth: Int? = null
    var assignedDepth: Int? = null
    var ascent: Int? = null
    var descRate: Int? = null
}
class Vehicle(...) : MovableUnit()

class Installation(...) : Unit(...)
class LandFormation(...) : Unit(...)
class ReferencePoint(...) : Unit(...)
class Sonobuoy(...) : Unit(...)
```

**兼容性策略**：Gson 反序列化时先读 `Domain` / `Type` / `Class` 字段，再实例化对应子类；序列化时写回统一字段。

#### 2.2.2 类型注册表（Domain Registry）

桌面版 `Fill*Types` 是运行时菜单数据源。Android 需要：

```kotlin
object UnitTypeRegistry {
    data class TypeInfo(
        val domainCode: String,      // A/U/I/B/L/R/S/V
        val typeName: String,        // "Aircraft" / "Surface Ship"
        val className: String,       // "Carrier" / "Submarine"
        val defaultSymbol: SymbolKey,
        val sizeLevel: SizeLevel?
    )

    val AIR_TYPES = listOf("Aircraft","Helicopter","Missile","AC Attack",...)
    val SURFACE_TYPES = listOf("Carrier","Battleship","Cruiser","Destroyer",...)
    // ...
}
```

#### 2.2.3 引擎层（Engine）

| 模块 | 职责 | 对应桌面版 |
|---|---|---|
| `MovementEngine` | 回合推进、单位移动、航路点归档、高度/深度变化 | `CMovableUnit.Move`, `CheckFutureWaypoints`, `ArchiveFutureWaypoint` |
| `TurnState` | 状态机（DO_BEFORE/DO_AFTER/DO_NEXT）、时间推进 | `Game.Turn.CTurn` |
| `FogOfWar` | 红蓝视角过滤、感知脱敏 | `CUnit.GetCurrentPerception` |
| `FormationEngine` | 队形准备/移动/撤销/列队 | `Formations.Movement.*` |
| `ReplayEngine` | 历史轨迹时间线构建 | `WindowTurnReplay` |
| `CalcEngine` | 方位/距离/新位置/到达时间 | `Game.CalcBearing/CalcRange` |

#### 2.2.4 数据层（Data）

| 模块 | 职责 |
|---|---|

#### 2.3.2 GameViewModel 新职责

只保留：
- 持有 `ScenarioFile` 引用
- 持有纯 UI 状态（selectedUnitId, editTarget, measureMode, replayState, symbolStyle, revision）
- 接收用户命令，调用后端 UseCase / Engine
- 把一次性事件暴露为 `SharedFlow`/`StateFlow`

不保留：
- 不再写具体业务算法（如 `duplicateUnit` 里手动 Gson 深拷贝、手动算新坐标）
- 不再直接调用 `repo.saveTo` 的细节

```kotlin
class GameViewModel(application: Application) : AndroidViewModel(application) {
    private val scenarioRepo = ScenarioRepository(application)
    private val movementRepo = MovementOrdersRepository(application)
    private val settingsRepo = SettingsRepository(application)

    // 后端引擎直接作为单例/注入
    private val movementEngine = MovementEngine
    private val formationEngine = FormationEngine
    private val replayEngine = ReplayEngine

    var scenario by mutableStateOf<ScenarioFile?>(null)
    var selectedUnitId by mutableStateOf<String?>(null)
    var editTarget by mutableStateOf<EditTarget?>(null)
    var symbolStyle by mutableStateOf(SymbolStyle.CWS)
    var revision by mutableStateOf(0)

    private val _events = MutableSharedFlow<UiEvent>()
    val events = _events.asSharedFlow()

    fun loadScenario(uri: Uri) = launch {
        scenarioRepo.load(uri)
            .onSuccess { applyLoaded(it) }
            .onFailure { _events.emit(UiEvent.Toast("加载失败：${it.message}")) }
    }

    fun doTurn() {
        val s = scenario ?: return
        if (!TurnState.canDo(TurnState.detect(s))) {
            emitToast("当前状态不可 Do")
            return
        }
        movementEngine.advance(s, s.time.currentTurnInterval)
        scenarioRepo.saveAuto(s)   // 后端自动存档
        revision++
    }

    fun editUnit(unitId: String) {
        val unit = scenario?.units?.find { it.idNum == unitId } ?: return
        editTarget = when (unit) {
            is AirUnit -> EditTarget.AirUnit(unit)
            is SurfaceUnit -> EditTarget.SurfaceUnit(unit)
            is SubsurfaceUnit -> EditTarget.SubsurfaceUnit(unit)
            // ...
        }
    }
}
```

### 2.4 前后端交互契约

| Frontend 动作 | Backend 调用 | 返回值/副作用 |
|---|---|---|
| 打开场景 | `ScenarioRepository.load(uri)` | `Result<ScenarioFile>` |
| 保存场景 | `ScenarioRepository.saveScenario(file, targetUri)` | `Result<SavedFiles>` |
| 自动存档 | `ScenarioRepository.saveAuto(file)` | 写文件 |
| Do 回合 | `MovementEngine.advance(file, interval)` | 修改 file + 返回 Range 耗尽列表 |
| Undo 回合 | `TurnState.undo(file, interval)` | 恢复 undoSnapshot |
| Next 确认 | `TurnState.confirmNext(file, interval)` | 推进状态 |
| 切换符号 | `GameViewModel.symbolStyle = ...` | UI 状态 |
| 编辑单位 | 打开对应类型 Dialog，改完后 `applyEdit(unit)` | 修改 file.units |
| 编辑航路点 | `WaypointService.update(unit, waypoints)` | 重算 bearing/arriveTime |
| 编辑感知 | `PerceptionService.update(unit, side, perception)` | 修改 perceptionArray |
| 绘制单位 | `SymbolRenderer.draw(canvas, unit, style, selected)` | 无状态 |
| 绘制弧 | `RangeArcRenderer.draw(canvas, unit, arc)` | 无状态 |
| 测量画线 | `CalcEngine.bearing/range(start, end)` | 纯计算 |

## 3. 按模块的详细开发计划

### 3.1 Phase 1：模型与引擎重构（高风险，优先）

#### 3.1.1 引入 Unit 类型继承体系

- 新增 `domain/model/unit/` 包
- 保留旧 `data.model.Unit` 作为 Gson 反序列化中间对象（`RawUnit`）
- 反序列化流程：`Json → RawUnit → typed Unit`
- 序列化流程：`typed Unit → RawUnit → Json`

#### 3.1.2 感知系统完整化

```kotlin
data class Perception(
    val seenBySide: String,
    val showAsSide: String,
    val showAsType: String,
    val showClass: Boolean,
    val showName: Boolean,
    val showCourseSpeed: Boolean,
    val showAltitude: Boolean,
    val showDepth: Boolean
)
```

- 每个 `Unit` 持有 `MutableList<Perception>`
- `FogOfWar.applyPerspective(file, side)` 按 `seenBySide == side` 过滤/脱敏
- UI 提供红蓝双方独立编辑

#### 3.1.3 RangeGraphics 传感器/武器弧绘制

- 新增 `domain/model/Arc.kt`：`MinRange/MaxRange/StartAngle/ArcAngle/IsFilled/ArcColor`
- 新增 `service/RangeArcRenderer.kt`
- 在 `SceneCanvas` 中先于单位绘制 Sensor/Weapon 弧
- 新增 `SensorWeaponEditorDialog`

### 3.2 Phase 2：前端对话框补齐

| Dialog | 说明 |
|---|---|
| `WaypointEditorDialog` | 列出 FutureWaypointArray，支持添加/删除/重算，显示 Bearing/ArriveTime |
| `NewPositionDialog` | 恢复被删除的功能：参考单位 + 方位 + 距离 → 新坐标 |
| `ConvoyDialog` | 恢复护航队创建：COMMODORE + 环绕 Merchant |
| `PerceptionEditDialog` | 按 Blue/Red 分 Tab 编辑感知 |
| `SettingsDialog` | 显示选项开关、颜色配置、玩家名 |
| `ExportOrdersDialog` | 选择单位导出运动命令 |

### 3.3 Phase 3：地图与符号完善

- `MapRenderer` 补齐 Cities/Countries/Waters/DepthLabels/BorderPolys
- `MercatorRaster` 解析 `.map/.txt` 光栅地图
- `SymbolGenerator` 补齐 WW2 符号
- `TrackHistory` 增强轨迹点样式

### 3.4 Phase 4：复制粘贴与编队增强

- `CopyPasteService` 按 Domain 分派 8 种类型复制
- `FormationEngine` 补齐 `DoPrepare/DoCancel/SearchForFormation/RemoveUnitFromFormation`

## 8. 附录：桌面版关键公式汇总

```text
方位角：ATan2(dy, dx) → 度 → 负数+360
距离：Sqrt(dx² + dy²)
移动：距离 = 速度 × 时间（整回合/分钟/秒）
位移：dx = 距离 × Sin(航向), dy = 距离 × Cos(航向)
新位置：ref + 距离 × (Sin方位, Cos方位)
到达时间：当前时间 + (距离/速度) 小时
队形 Course 模式：成员偏移按中心航向旋转
队形 Compass 模式：成员偏移按罗盘角直接叠加
```

这些公式在当前 Android 实现中已基本正确，重构时直接迁移即可。
